# Failures & Technical Debt

- 2026-05-16: NewsGraph click detection was still failing for many users because the tolerance (dist < 5px, time < 300ms) was far too strict for trackpads or slow clicks. Increased to 15px and 800ms. Additionally, the hover/active state was destructively overwriting the node's native semantic color with a flat red; updated canvas renderer to preserve the topic color and apply a stroke/glow instead.
- 2026-05-16: Retrieval Vector card in LiveNewsGraphPage had invisible text due to a CSS specificity conflict. The global `.bento-shell` class forced `background: #ffffff`, overriding the inline `bg-[#1c1917]` utility class, resulting in white text on a white background. Resolved by removing the `.bento-shell` class from the dark card.
- 2026-05-16: **News modal showing only title (ROOT CAUSE FOUND)**: `getArticleUrl()` in `live-home.tsx` checked `story.id.startsWith("http")` but story IDs have the format `story:gdelt:https://tass.com/...` — they start with "story:", not "http". So the URL was never extracted, `/api/fetch-article` was never called, and the modal showed only the title with an empty body. Fix: used regex `story.id.match(/https?:\/\/.+/)` to extract embedded URLs. Also fixed a `useEffect` dependency bug where `selectedStory` (a new object reference on each 15s auto-refresh) caused the fetch to be continuously cancelled and re-triggered.
- 2026-05-16: **Bookmarks were purely decorative** — the button had no state or handler. Added `bookmarkedStories` Set state and `toggleBookmark` handler for visual toggle.
- 2026-05-16: **"READ ORIGINAL" button silent failure** — `openOriginal` relied on `getArticleUrl` which returned null for most stories (see root cause above). Fixed by also checking `article?.finalUrl` from the fetch-article API response.
