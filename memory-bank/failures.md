# Failures & Technical Debt

- 2026-05-16: NewsGraph click detection was still failing for many users because the tolerance (dist < 5px, time < 300ms) was far too strict for trackpads or slow clicks. Increased to 15px and 800ms. Additionally, the hover/active state was destructively overwriting the node's native semantic color with a flat red; updated canvas renderer to preserve the topic color and apply a stroke/glow instead.
- 2026-05-16: Retrieval Vector card in LiveNewsGraphPage had invisible text due to a CSS specificity conflict. The global `.bento-shell` class forced `background: #ffffff`, overriding the inline `bg-[#1c1919]` utility class, resulting in white text on a white background. Resolved by removing the `.bento-shell` class from the dark card.
- 2026-05-16: **News modal showing only title (ROOT CAUSE FOUND)**: `getArticleUrl()` in `live-home.tsx` checked `story.id.startsWith("http")` but story IDs have the format `story:gdelt:https://tass.com/...` — they start with "story:", not "http". So the URL was never extracted, `/api/fetch-article` was never called, and the modal showed only the title with an empty body. Fix: used regex `story.id.match(/https?:\/\/.+/)` to extract embedded URLs. Also fixed a `useEffect` dependency bug where `selectedStory` (a new object reference on each 15s auto-refresh) caused the fetch to be continuously cancelled and re-triggered.
- 2026-05-16: **Bookmarks were purely decorative** — the button had no state or handler. Added `bookmarkedStories` Set state and `toggleBookmark` handler for visual toggle.
- 2026-05-16: **"READ ORIGINAL" button silent failure** — `openOriginal` relied on `getArticleUrl` which returned null for most stories (see root cause above). Fixed by also checking `article?.finalUrl` from the fetch-article API response.
- 2026-05-17: **Full article content not available** — Mozilla Readability alone failed to extract content from many modern websites with complex layouts, anti-bot protection, or non-standard HTML structure. The API returned empty `html` and `text` fields, triggering the "Full article content is not available" message. **Resolution**: Implemented three-tier extraction strategy: (1) Readability as primary, (2) Cheerio fallback that searches for article body selectors and extracts meaningful paragraphs, (3) Raw text extraction from DOM nodes as last resort, (4) Description/title fallback. Frontend now has improved fallback chain showing story content, description, or metadata card when extraction fails.
- 2026-05-17: **Placeholder stories showing empty content** — When RSS/API sources failed, fallback stories were generated with generic titles like "Yahoo Finance placeholder signal #1" and no content. **Resolution**: Added realistic content snippets to fallback generator for each source type, implemented Google News RSS as universal fallback when primary sources fail, improved RSS content extraction and preservation.
- 2026-05-17: **Pre-existing build error** — `app/api/horizon/route.ts:68` has a TypeScript error where `null` values in array are not assignable to `HorizonItem[]`. Unrelated to article extraction fix, needs separate attention.
- 2026-05-17: **Homepage fetched full articles on click instead of routing** — `LiveHome` opened an overlay and called `/api/fetch-article` directly, so news cards did not produce SEO/shareable URLs and homepage interactions triggered expensive full-content extraction. **Resolution**: Removed the homepage article reader path, added dynamic `/news/[slug]` pages, and converted cards/graph node clicks to route navigation with article fetching isolated to the article page.
- 2026-05-17: **Next.js route config re-export error** — Initial `/news` alias re-exported `dynamic` from `../page`, which Next.js cannot statically analyze. **Resolution**: Defined `export const dynamic = "force-dynamic"` directly in `app/news/page.tsx` and default-exported the imported page component.
- 2026-05-17: **Verification still blocked by existing repo debt** — `bun run check-types` remains blocked by unrelated existing errors in Horizon API item typing, custom `dotlottie-player` JSX types, old `NewsModal` price/volume fields, missing `axios`, and source-adapter strictness. `bun run lint` remains blocked by existing warnings because the script uses `--max-warnings 0`.
- 2026-05-17: **Article detail dead-end for placeholder stories** — Some cached or fallback stories reached `/news/[slug]` without a fetchable article URL and without article extraction output, causing users to see two unhelpful messages: "Original source URL is not available for this story." and "Full article content is unavailable from this source." **Resolution**: The article page now derives a fallback coverage link from `SOURCE_DEFINITIONS`, suppresses those dead-end errors when fallback copy exists, and renders a synthesized summary when no extracted body is available.
